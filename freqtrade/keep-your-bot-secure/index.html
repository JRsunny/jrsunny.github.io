保持你的机器人安全

发表于2026-09-22|更新于2026-10-09|freqtrade教学服务器运维
|阅读量:

原文标题：Keep your bot secure
原文链接：https://botacademy.ddns.net/2026/09/22/keep-your-bot-secure/
发布日期：2026-09-22

过去几天里，至少有两个 FT 用户的机器人被黑（或被尝试入侵）。我们来详细聊聊这两个案例。

第一个用户（大概率）是 Telegram 账号被黑了。事情是这样的，他们的 Telegram 机器人突然发出了下面这段对话。

首先，Freqtrade 不会从交易所收到任何更新通知，所以 Freqtrade 根本没办法提醒你。其次，你无法通过 API 端点修改 config。这是我们特意加的限制，就是为了防范这类黑客攻击。

所以我认为这个钓鱼手法是这样的。黑客只能看到受害者（我们叫他 A）的 Telegram 消息。他们无法访问 A 的 vps。虽然 FT 有 /show_config 命令，但 API 信息不会从中返回。所以他们试图做的是让 A 去修改自己的 API 凭证，并指望 A 忘了设置 IP 白名单（这也是上面那段对话里没提到它的原因）。如果 A 改了 API 凭证，并按指示输入 /config 加上新的 API 凭证，A 的 FT 机器人会忽略这个命令，因为它根本不存在。但黑客现在已经知道了 API 凭证（记住，他们已经黑进了 A 的 Telegram 账号）。

一旦他们拿到那个 API 凭证，并且如果没有设置 IP 白名单，他们就能开始掏空 A 的钱，即使没有启用/勾选 Withdrawals 权限也一样。他们需要的只是交易权限。

有一件重要的事要记住：如果你在机器人 config 里启用了 force entry，而你的 Telegram 账号被黑了，那么黑客可以跳过上面的钓鱼步骤，直接掏空你的钱。所以从 A 的案例中得出的重要教训是：

  1. 保护好你的 Telegram
  2. 在确认来源之前，不要点击随机链接
  3. 如果你不是真的需要，就不要启用 force entry

好在 A 先在 FT discord 服务器上问了，所以（我猜）没有损失钱。遗憾的是，第二个用户（我们叫他 B）就没这么幸运了。

B 的案例其实是一个很多新用户都犯过的常见错误，不管是有意还是无意。主要原因是他们把 docker-compose.yml 里的端口部分设置成了 “0.0.0.0:8080:8080”，从而把 API 暴露到了互联网上（这一点在这里已经警告过），再加上他们没有修改 config 里的 jwt_secret_key。由于他们知道了 JWT，就不需要 API 用户名和密码了，这就是为什么像这里提到的那样，设置一个随机 JWT 非常重要。

一旦黑客获得了 API 访问权限，掏空 B 比 A 的案例更容易，因为掏空命令来自白名单 IP（如果设置了的话）。再说一次，不需要提现权限。所以永远不要以为只要没启用提现权限，你的 API 就是安全的。

B 案例的主要教训很简单（但很多新用户却试图无视我们的警告）：永远不要把 frequi（也就是 API 端点）开放到互联网上。如果你需要一种不用 SSH 隧道就能方便访问机器人的方式，可以使用 Tailscale 或类似服务。当然，如果你某台（连接到 tailnet 的）设备被黑了，你仍然可能被黑，但那是另一回事了。

如果你想向别人炫耀你机器人的成绩，请考虑用 discord webhook 来做交易通知。你也可以创建一个单独的只读站点，作为普通人和你的 FT 机器人之间的桥梁。永远不要把你的机器人直接暴露到互联网上。只需要一个小错误，攻击者就能拿到你的钱。
