如果你已经做到了上面两点，但还想进一步减少内存占用，并且能接受更长的 hyperopt 完成时间，那么你可以用这两种方法

把 job 数量限制为 1（针对 hyperopt）

正如开头所说，hyperopt 其实就是并行执行的 backtest。遗憾的是，它们不会在各个 backtest 之间共享 dataframe。这意味着你用的 CPU 核心越多，占用的内存就越多。要想尽可能少用内存，你需要把使用的 CPU 核心限制为 1。

把只用一次的指标放到各自对应的函数里计算

例如，你的入场逻辑只用到 ema_15。与其在 populate_indicators 里计算这个指标并把值存进 dataframe（也就意味着它被存进了内存），你完全可以在 populate_entry_trend 里这样计算

这样你会省下内存，但完成时间会更长，因为这意味着 ema_15 会在每个 epoch 都被计算一次，而如果你把它放在 populate_indicators 里就只会计算一次。对于 backtest 来说，完成时间变长这个代价可能微不足道，因为无论哪种方式你都只计算一次。
