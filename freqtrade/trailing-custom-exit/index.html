追踪自定义退出

发表于2023-10-15|更新于2026-10-09|freqtrade教学策略技巧与代码片段
|阅读量:

原文标题：Trailing Custom Exit
原文链接：https://botacademy.ddns.net/2023/10/15/trailing-custom-exit/
发布日期：2023-10-15

默认情况下，Freqtrade 已经自带 custom_exit 和 custom_stoploss 函数。尽管名字不同，实际上两者非常相似，可以互换使用，只要你知道它们之间的区别就行。它们之间有两个相当显著的主要差异

Trailing stop 与立即退出

如果你使用 custom_stoploss，退出会以 trailing stoploss 的形式进行，而 custom_exit 则是立即退出。两者各有优缺点。有些人偏好立即退出带来的固定利润保证，而有些人则愿意尝试跟随绿色 K 线，代价是当绿色 K 线不如预期强劲时利润会减少。

退出标签

你无法在 custom_stoploss 上设置退出标签。所有使用它的退出都会被标记为 trailing stoploss。虽然在 dry/live run 中这可能没问题，但对 strategy 开发来说并不理想，因为你可能想知道每个退出逻辑的表现如何，以及哪个需要进一步调整。

这就是我提出 Trailing Custom Exit 的原因。思路很简单。在 backtest 中，把你的退出逻辑放进 custom_exit（而不是 custom_stoploss）。你就能在 backtest 输出中得到退出标签，并且可以根据需要调整它们。然后在 dry/live run 中，使用我的代码片段把 custom_exit 转换成 custom_stoploss。

需要做的事

  • 只复制从第 5 行开始及以下的内容。把它们放到与你的 strategy 相同的文件中，位于主 strategy 类下方
  • 把 your_base_strategy_class_name 改成你想继承的 strategy 的实际类名
  • 把 trailing_custom_exit 类名改成你偏好的新名称
  • 在第 26 行，我加了一段代码，用于向你的 telegram/webhook（如果你使用其中任何一个）发送消息，让你知道 custom_exit 中触发了哪个退出标签。存入数据库的退出原因会是 trailing_stop_loss，所以把实际标签发送到你的 telegram/webhook 对后续使用会很有帮助。如果你不想收到消息，可以删掉那一行
  • 在第 36 行，把 trailing 改成你偏好的数字。而且既然我们已经存储了退出标签，你也可以为每个退出标签设置不同的 trailing。在那里写 if else 块就行（我相信这个不用我教你）
  • 在做 backtest/hyperopt 时使用原来的类名，在 dry/live run 配置中使用新名称

正如名字所说，这只会把 custom_exit 转换成 trailing。其他退出（populate_exit_trend、roi、stoploss）仍然是立即退出。我正在努力把 populate_exit_trend 也变成 trailing，但目前仍在进行中。
