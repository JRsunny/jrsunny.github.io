为什么NostalgiaForInfinity不应用于实盘交易

在没有 backtest 证据的情况下，把有问题的交易币种拉黑

在出现一笔巨额亏损交易后就把某个币种拉黑，并不能保证未来不会在另一个币种上出现类似的巨额亏损。每天都有新币种上线，尤其是在审核不那么严格的交易所。最好的做法是：在实盘交易中屏蔽某些币种，但同时也要改进 strategy，确保新版本的 backtest 能够应对那些有问题的币种。虽然这不能百分百保证，但至少你的 strategy 现在能处理之前已经识别出的不良交易了。

不设硬 stoploss，因为它会反弹

这是一种危险的思维方式，尤其是在加密货币世界里——除了 Bitcoin 之外，任何币种都可能跌进深坑。还记得 LUNA 吗？或者那些 metaverse 币，比如 MBOX？它们并不总会反弹。使用非常宽松的 stop loss，并随意上下调整，风险极高。有时候，stoploss 会在上次调整后仅仅几天就被再次改动。要么设定固定的 stop loss，要么使用宽松的 stop loss 并配合多套退出方案，以便在指标开始尖叫“危险！”时使用。完全不设 stoploss 就是糟糕的风险管理。一次亏损就可能基本上抹掉数周甚至数月的利润。

“精妙复杂”的 strategy

说实话，要逐行阅读和分析 strategy 文件里的每一行代码需要大量时间，而这正是每个人在使用不熟悉的 strategy 之前必须做的事。你必须完全理解这个 strategy 是如何运作的。遗憾的是，没有多少人愿意在把真金白银投入实盘之前耐心等待。

过拟合式的修改

看看这个修改，把 0.022 改成了 0.023。没有任何逻辑推理，仅仅是为了让 backtest 看起来完美无瑕，就对参数做了如此微小的调整。再看这个修改，把 0.990 改成了 0.995。这个呢？这个呢？除了这些调整会带来好看的 backtest 结果之外，我希望这些调整背后还有一些合乎逻辑的科学依据。

就我个人而言，我建议坚持使用一个固定的数字，比如 0.95。同时，如果你仍然想改动这个数字，最好使用合适的步长；举例来说，如果范围是 0 到 1，那么 0.005 的增幅就可以被视为过拟合。防止过拟合的理想增幅是 0.05。但如果范围是 0 到 0.1，那么 0.005 也是可以的。最好的做法是增加额外的逻辑，而不是改变参数的值。

更新太频繁

很少有某个版本会被长期运行，以评估其实际表现并与 backtest 进行对比。有时候你甚至一天能收到 6-7 次更新。因为几个小时后就会有更新的版本，所以很难判断之前的版本是否真的很差，以及新版本是否更好。所有评估都基于 backtest 结果，但正如我后面会讨论的，这些结果是有问题的。

这些频繁的更新唯一做到的事情，就是助长了 FOMO 心态。用户中普遍存在一种误解，认为越新就越好。并没有确凿的证据支持这一点。而且由于每个版本的改动都很微小，也很难确定最新版本中究竟是哪些部分真正导致了表现的提升或下降。

自定义 exit 以及欺骗 backtest 的部分入场/出场

想了解自定义 exit 中陷阱的成因以及如何避免，请点击上面的链接。在 exit 逻辑中写一长串 if-else 逻辑，几乎总会让你得到与 backtest 不同的结果，因为很难达到与 backtest 相同的入场率。你甚至会在两个同时运行的 bot 上得到不同的结果。部分入场/出场的问题与上面提到的自定义 exit 陷阱有同样的毛病。

不一致的 startup_candle_count

这很奇怪，因为 startup_candle_count 被定义为 800，但下面几行却写着

Startup candle 是一个取决于你所用指标的参数，而不是取决于你所用交易所的参数，因为如果草率地减少 startup 数量，会对许多指标产生影响。简单看一下 populate indicators，就会发现有几个指标如果在 Bybit 上使用这种方法就会出问题。

我的讲师经常说一句话：“垃圾输入，垃圾输出。”如果你给指标提供不准确的数据，就别指望它们能给你可信的结果。如果你认为某个交易所无法处理这样的 candle 请求，那就不要支持它。安全行事总比拿着劣质武器去战斗要好。

由于硬 stoploss（在撰写本文时）被设定在 30%，实际只要波动 6% 就足以触发它。结合 NFI 各变体的历史以及当前实盘交易记录来看，-6% 并不罕见。我们其实并不清楚这个 strategy 在期货市场上会带来什么结果，因为到目前为止我还没看到任何针对它的 backtest 结果。如果你打算在期货上使用这个 bot，在投入真金白银（live）之前，请务必做充分的 backtest 和长时间的 dry run。
