简单的附加条目代码

重要免责声明！！！

目前我本人不使用额外入场。在我看来，额外入场往往弊大于利。你只是在把亏损挖得更深。不过，也许你能用得比我更好。请做充分的测试，看看它是否真的对你有帮助。

接下来进入正题……

这段代码只会在机器人初始入场的基础上做额外入场。不会有部分退出。概念非常简单，当 current_profit 达到 initial_safety_order_trigger 时，会触发第一次额外入场。第一次之后，后续入场的触发条件将由 safety_order_step_scale 决定，stake 数量将由 safety_order_volume_scale 决定。

注意事项

  • 如果你现有的 strategy 已经导入了第 1 到 7 行，就不需要再复制。否则，请补上缺失的 import
  • 把 strat_dca 改成你想要的新名字
  • 把 yourstrat 改成基础 strategy 的实际类名
  • 修改第 15-18 行以符合你的偏好。你可以用下面的电子表格来帮你。
  • 复制第 11 行及以下内容，粘贴到基础 strategy 下面
  • 使用的 current_profit 只会基于上一根 K 线的收盘价计算。这意味着它不会跟随当前 tick 价格的变化。这样做是为了确保 backtest 行为能尽量贴近 dry/live 的表现。如果你不想要这种行为，可以删除第 38-40 行，但要知道这会让你的 strategy 在 backtest 与 dry/live 之间的表现出现显著差异。
  • 这段代码每根 K 线只会做一次额外入场，这意味着机器人在当前未收盘 K 线上做了额外入场后，无论当前 K 线跌得多深（做空则是涨得多高），都不会再做额外入场，直到下一根 K 线。这样做是为了确保 backtest 行为能尽量贴近 dry/live 的表现。如果你不想要这种行为，可以删除第 49 行并调整第 50-67 行的缩进，但要知道这会让你的 strategy 在 backtest 与 dry/live 之间的表现出现显著差异。

你可以查看这里的电子表格，看看它会如何运作。里面有两张表，calc 和 example。你只能修改 calc 表中蓝色高亮单元格的值。

另外你需要注意绿色列中的数值。根据你设置了多少次额外入场，你需要准备相应的 stake 数量。所以如果你看 example 表，假设我想允许 5 次额外入场，那么每个交易槽位需要准备 252.144 USDT。所以如果你把 max_open_trades 设为 5，那么机器人可用的余额需要大约 1265 USDT。

还有一点需要注意，由于这个示例是为做多方向交易创建的，当 loss before extra entry 超过 100% 时，单元格会被标红，就像你在 example 表中看到的那样。所以以这个示例来说，这意味着 5 次额外入场是你所能拥有的最大上限。你可以设置超过 5 次，但不会有任何作用（在做多交易中）。如果你做的是做空交易，那么可以忽略红色警告。

代码如何运作

当亏损等于或大于 initial_safety_order_trigger 时，会发生第一次额外入场。它的 stake 数量将等于原始入场的 stake 数量。第一次之后，额外入场的亏损触发条件和 stake 数量可能会根据你的 safety_order_step_scale 和 safety_order_volume_scale 设置而改变（用电子表格来调整这些设置试试看）。

总结

这是一段非常简单的额外入场代码。你可以修改它来提升表现，比如加入指标检查。尽情发挥创意吧。
