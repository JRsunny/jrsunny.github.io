多个机器人共用一个钱包

发表于2024-07-27|更新于2026-10-09|freqtrade教学心得与认知
|阅读量:

原文标题：Multiple bots using one wallet
原文链接：https://botacademy.ddns.net/2024/07/27/multiple-bots-using-one-wallet/
发布日期：2024-07-27

理想情况下，每个 bot 使用一个 wallet，但在同一个交易所账户里拥有多个 wallet 并没有那么容易。有些交易所可能会免费提供子账户，这样你就可以给每个 bot 分配不同的子账户（不过子账户数量有上限，所以如果你有很多 bot，可能还是会遇到同样的问题）；而另一些交易所要么没有这个功能，要么只对特定等级的用户开放，这意味着你不得不用一个 wallet 来跑多个 bot。

能不能让多个 bot 共用一个 wallet？可以的。你只需要确保用 available_capital 而不是 tradable_balance_ratio 来设置每个 bot 的余额。给每个 bot 分配多少，取决于你自己的判断和对 bot 的了解。

举个例子，我的 wallet 里有 1000 USDT，我有 20 个 bot。我可以有多种分配方式，比如：

  • 平均分配，也就是每个 bot 分到 50 USDT。如果我想采用最佳的风险管理方式，或者你预测/设计的 strategy 会出现所有 bot 同时活跃交易的情况（比如 BTC 暴跌的时候），我就会这么做
  • 也可以给每个 bot 更多资金，比如 100 USDT。如果我知道所有 bot 同时开单的概率非常低，我就会用这个方案。这样就不会出现因为 wallet 里没钱导致某些 bot 无法开单的问题。

除了分配资金之外，针对不同的市场，还有一些你需要了解的具体问题

现货市场

如果你要在单个现货 wallet 里跑多个 bot，唯一需要担心的就是交易手续费是怎么扣的。你可能会想，手续费怎么会引发问题？让我举个简单的例子

假设我有 100 USDT。我想以 $1 的价格买入 DOGEUSDT 交易对。我能买到多少 DOGE？如果你的答案是 100 DOGE，那么根据我 wallet 里实际有多少钱，你可能对也可能错。假设交易手续费固定为 0.1%，也就是说对于 100 USDT 的买单，我需要支付 0.1 USDT 的手续费。

  • 如果我的 wallet 里有更多钱，比如有 200 USDT，那么手续费会从多余的钱里扣，所以如果买单成交，我会得到 100 DOGE 和 99.9 USDT
  • 但如果我的 wallet 里刚好只有 100 USDT，那么手续费会从 bot 的钱里扣，也就是说买单成交后，我只会得到 99.9 DOGE。

把这个概念套用到有多个 bot 的场景。假设我有 300 USDT，平均分给 3 个 bot。

  • Bot #1 买入价值 100 USDT 的 DOGE。因为 wallet 里有多余的钱，买入手续费从多余的钱里扣。买单成交后，我的 wallet 里会有 100 DOGE 和 199.9 USDT。
  • Bot #2 想再买入价值 100 USDT 的 DOGE。和 bot #1 类似，因为 wallet 里有多余的钱，手续费从里面扣，也就是说买单 #2 成交后，我的 wallet 里会有 200 DOGE 和 99.8 USDT
  • 当 bot #3 想开单时，它会假设自己还有同样的 100 USDT，但实际上 wallet 里只剩下 99.8 USDT。假设 bot #3 仍然能下买单。因为现在 wallet 里没有多余的钱了，买入手续费会从可用资金里扣，也就是说 bot #3 只能买到 99.7002 DOGE。所以最终，你的 wallet 里会有 299.7002 DOGE 和零 USDT。

你可能会问，问题出在哪？第一个问题是 bot #3 的交易额低于上限，所以利润会比它有完整 100 USDT 时更少。第二个问题会在卖出的时候出现。

假设到了三个 bot 都想卖出 DOGE 的时候。关于买入手续费的规则同样适用于卖出手续费。

  • Bot #1 卖出 100 DOGE。0.1 DOGE 的手续费从 wallet 里扣。剩下 199.6002 DOGE。
  • Bot #2 卖出 100 DOGE。0.1 DOGE 的手续费从 wallet 里扣。剩下 99.5002 DOGE。
  • Bot #3 想卖出它的 99.7002 DOGE，但发现 wallet 里的数量（99.5002）比它少。它会卖出失败。你只能手动卖出。

避免上述问题的最佳方式是，要么在 wallet 里预留一部分闲钱用来支付手续费，要么使用交易所的手续费抵扣币来支付手续费，比如 binance 的 BNB 和 kucoin 的 KCS。当数量不足时，你需要手动买入手续费抵扣币，因为 bot 自己没法买。

期货市场

对于期货，交易手续费的问题依然存在，但只存在于开仓手续费。至于平仓手续费，会在平仓单成交后从你的 wallet 里扣，所以不会出现现货市场里那种平仓失败的情况。

可能出现的致命问题是，当两个或多个 bot 朝不同方向交易时，比如一个 bot 开多仓，另一个 bot 开空仓。虽然两个 bot 开仓都不会有问题，但它们平仓时都会遇到麻烦。原因是平仓单的 reduce only 选项被设置为 true。让我用一个简单的例子来解释。

Bot A 开了一笔 0.03 BTC/USDT:USDT 的多单。在 wallet 里，记录显示你有 0.03 BTC/USDT:USDT。1 根 K 线之后，bot B 开了一笔 0.03 BTC/USDT:USDT 的空单。在 wallet 里，记录显示你有零 BTC/USDT:USDT。问题出现在其中任何一个想平仓的时候

  • 当 bot A 想平仓时，意味着它需要卖出 0.03 BTC/USDT:USDT。问题是，如果它下了一个 0.03 BTC/USDT:USDT 的卖单并成交，你的 wallet 余额会变成负数，而由于 reduce only 被设置为 true，这是不允许的。Bot A 会平仓失败。
  • 当 bot B 想平仓时，意味着它需要买入 0.03 BTC/USDT:USDT。问题是，如果它下了一个 0.03 BTC/USDT:USDT 的买单并成交，你的 wallet 余额会变成正数，而由于 reduce only 被设置为 true，这是不允许的。Bot B 会平仓失败。

所以，如果你想在单个 futures wallet 上运行多个机器人，极其重要的一点是：确保它们在任何时候都不会开出方向相反的交易。
