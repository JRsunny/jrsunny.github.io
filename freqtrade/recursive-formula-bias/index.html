递归公式偏差

发表于2023-07-20|更新于2026-10-09|freqtrade教学策略技巧与代码片段
|阅读量:

原文标题：Recursive formula bias
原文链接：https://botacademy.ddns.net/2023/07/20/recursive-loop-bias/
发布日期：2023-07-20

20230804：底部新增了信息，以强调这种偏差可能有多关键

“lookahead bias（前视偏差）”这个词，指的是你的机器人在 backtest 过程中某个时点看到了未来的数据，并因此影响了它的入场和/或出场决策，这个概念对你们大多数人来说应该都不陌生。但什么是“Recursive loop bias（递归循环偏差）”呢？

举个例子会更容易解释。假设我有一个非常基础的指标叫 steps。第一行的值始终是 0，而后面的行则等于上一行的值加 1。假设我想 backtest 一个我在 1d timeframe 上运行、时间范围为 20230101-20230201 的 strategy。那么我在 20230101 这根 K 线上的 steps 值是 0，而在 20230131 这根 K 线上的 steps 值则是 30。

但是，如果我的 backtest 范围是 20230115-20230201 呢？那么我在 20230115 这根 K 线上的 steps 值是 0，而在 20230131 这根 K 线上的 steps 值就会是 16。由于同一根 K 线在两个时间范围下的 step 值不同，两个时间范围的 backtest 结果可能会有细微差异。我把这称为 Recursive loop bias。

由于第一行在新 K 线到来后总会发生变化，这种偏差也可能影响你的 dry/live run。受这种偏差影响，你可能会在某些 K 线上看到之前并不存在的入场/出场信号，反之亦然。

具有这种偏差的指标例子是 pandas-ta 中的 Ehler’s Super Smoother Filter。这个函数的问题甚至更严重，因为前 3 行的值取自未来的数据（lookahead bias）。所以这个函数同时具有 lookahead 和 recursive loop 两种偏差。这就是有问题的那些行（未来可能会被修复）

这个问题没有可行的解决方案。唯一的选择是要么不使用这个指标，要么如果你必须比较两个结果，就确保两者使用相同的起始时间。这样至少指标的值在两次 backtest 中会是一样的。

测试结果

所以我做了一个简单的递归测试，看看在给定不同起始时间的情况下差异会有多大。我的测试方法相当简单

  • 用给定的 timerange 做一次完整的 backtest，并使用 strategy 内定义的 startup candle 数量
  • 完整 backtest 完成后，再用一个非常小的 timerange（相同的结束时间，但起始时间只比结束时间早 1 根 K 线）做几次较小的 backtest，但使用不同的 startup candle（200、500、1000、2000）。这些 backtest 将模拟 dry/live run 中发生的情况

有几点需要注意

  • 如果你看到 nan%，那意味着该指标返回了 null 值，也就是提供的数据不足以完成它的计算。比如，对于 startup candle 为 200 的情况，任何 200 周期的移动平均都无法计算。
  • 如果你使用 EMA 并且想用较长的长度，建议使用 EMA 长度的三到四倍的 startup candle。
  • 如果你使用任何把 EMA 作为其计算一部分的指标，你可能需要更长的 startup candle。比如对于 TEMA，你可能需要让 startup candle 等于 TEMA 长度的八倍。对于 EWO，你需要 slow EMA 长度的十倍。

你可以使用 recursive-analysis 命令 自己做测试。这是我用来得到上述结果的 strategy。启动递归测试的命令是 freqtrade recursive-analysis --config <your config.json> --strategy <your strategy> --timerange=<any timerange you usually use for backtest> -p <one pair>

需要注意的事项

  • 它一次只能检查一个 strategy
  • 由于它不关心任何交易，为了让过程更快，建议在做递归测试时关掉入场和出场趋势
  • 为了让它更快，测试时只用一个 pair。除第一个 pair 之外的任何额外 pair 都会被忽略。
